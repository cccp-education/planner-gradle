== Dcisions architecturales (cadrage S-074)

. *Porte EPIC* : faire consommer `AgentState` N0 par codebase (N1) comme
  tat du graphe koog, en remplaant `AugmentedState` + `PlanState` locaux
  par `AgentState.ContextReady`/`Classified`/`Planned`. Planner (N2) reste
  stateless — il recoit un tat et retourne un plan, le lifecycle est
  gr par codebase. *Codebase HORS SCOPE initial* — borough DORMANT, 
  r-valider si ractiv.
. *Porte planner (N2)* : planner expose une API lifecycle-aware optionnelle.
  `IntentionPlanner.plan()` accepte un `AgentState.ContextReady` (ou
  `Classified`) et retourne un `AgentState.Planned`. Backward compat :
  si l'appelant passe une `PlanningContext` simple (path actuel), planner
  construit un `AgentState.ContextReady` interne (adaptateur local).
. *Backward compat critique* : `PlannerIntegration.kt` (codebase) appelle
  `IntentionPlanner.plan(4 String + Logger)`. Le contrat d'appel est
  prserv — planner reoit toujours 4 String. L'API lifecycle-aware est
  une *surcharge optionnelle*, pas un remplacement.
. *Dpendance cross-borough BOM* : aucune nouvelle publication —
  `agent-contracts` 0.0.3 est dj dans le classpath de planner
  (`build.gradle.kts:29`). `AgentState`/`ContextAssembler`/`PlanExecutor`
  sont dj disponibles. Zro bump BOM.
. *Dpendance cross-borough codebase* : HORS SCOPE initial. `KoogAugmentedContextGraph`
  et `PlanState` bénéficieront de `AgentState` N0 dans un EPIC futur
  codebase (rgles de migration `AugmentedState`/`PlanState` → `AgentState`
  + suppression redondance). Borough Queens DORMANT.
. *Adapter pattern* : `LifecycleAdapter` (object pur, domaine
  `planning.lifecycle`) qui mappe `PlanningContext` + 4 canaux →
  `AgentState.ContextReady` (N0) et `Plan` → `AgentState.Planned` (N0).
  Fallback : si `AgentState` indisponible (exception) → path actuel
  (`PlanningContext` simple, `Plan` simple).
. *Testabilit* : `AgentState` N0 est pure (sealed class immutable).
  `LifecycleAdapter` est pur aussi. Tests unit + functional + Cucumber BDD.
. *Non-rgression critique* : `PlannerIntegration.kt` (codebase) appelle
  `IntentionPlanner.plan(eagerContext, ragContext, graphifyContext, docsContext)`.
  Le contrat d'appel est inchang — planner reoit toujours 4 String.
  L'API lifecycle-aware est additive, pas destructive.
. *Mthode* : baby-step DDD/TDD/BDD, 3 niveaux tests/US
  (unit → functional → cucumber), English only code/Gherkin.
. *Ordre* : US-1 (adapter, indpendant) → US-2 (wiring surcharge optionnelle)
  → US-3 (Cucumber).

== Porte codebase (HORS SCOPE initial)

Codebase gre son propre lifecycle koog (`KoogAugmentedContextGraph` +
`AugmentedState` + `PlanState`). La migration vers `AgentState` N0 est
un EPIC futur codebase (borough Queens DORMANT) :

. `AugmentedState` → `AgentState.ContextReady`/`Classified` (selon phase)
. `PlanState` → `AgentState.Planned`
. `KoogAugmentedContextGraph` nodes consomment `AgentState` au lieu de `AugmentedState`
. Suppression redondance `AugmentedState`/`PlanState` locaux

Cet EPIC est *planner-only* — codebase reste DORMANT. La porte planner
est d'exposer l'API lifecycle-aware pour que codebase puisse la consommer
le jour venu (sans changement planner).
