== Mission

Cadrage EPIC PLN-LIFECYCLE — planner consomme les types lifecycle N0
(`contracts.agent.AgentState` : ContextReady/Planned) pour s'articuler avec
le runtime agentique. Split-brain #3 reporté S-061.

== Constats

Audit planner + BOM : `agent-contracts:0.0.3` (N0) expose `AgentState`
mais planner ne le consomme pas — `IntentionPlanner` travaille avec
`PlanningContext` local et 4 String de canaux, sans état typé lifecycle.

== Décisions architecturales

. *EPIC planner-only* — codebase HORS SCOPE (Queens DORMANT).
. *Domaine `planning.lifecycle`* — 7ème domaine planner.
. *Adapter `LifecycleAdapter`* — object pur, mapping `PlanningContext` +
  4 canaux → `AgentState.ContextReady`, `Plan` → `AgentState.Planned`.
. *Surcharge optionnelle additive* — l'API lifecycle-aware n'est pas
  destructive, le stdout legacy `[PLAN]/[EPIC]/[US]/[TASK]` est préservé.
. *Flag opt-in* `-Pagent.lifecycle=true` (défaut `false`).
. *Zéro bump BOM* — agent-contracts 0.0.3 déjà classpath.
