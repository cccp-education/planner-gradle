== Audit — 3 constats factuels

=== Constat 1 — VibecodingStep a 3 champs de vérification

`codebase-plugin/src/main/kotlin/codebase/koog/planning/VibecodingPlan.kt:10`

[source,kotlin]
----
data class VibecodingStep(
    val description: String,
    val gradleTask: String,
    val expectedOutput: String,
    val maxRetries: Int = 3,
    val verifyHook: String? = null
)
----

`StepVerifier.verifyAndAdapt` (`StepVerifier.kt:17`) consomme
`step.maxRetries` + `step.expectedOutput` pour décider retry/give-up +
construire le prompt de replan (`buildReplanPrompt` ligne 88
`step.expectedOutput`). Contract de vérification codebase.

=== Constat 2 — GradleTask N0 n'a aucun champ de vérification

`workspace-bom/agent-contracts/src/main/kotlin/contracts/agent/AgentState.kt:126`

[source,kotlin]
----
data class GradleTask(
    val description: String,
    val gradleTask: String,
    val toolType: TaskType = TaskType.GRADLE,
    val target: String = "",
    val project: String = ""
) {
    init { /* 3 invariants description/gradleTask/target */ }
}
----

Pas de `expectedOutput`, pas de `maxRetries`, pas de `verifyHook`. Le
planner ne peut pas exprimer l'expectation d'une tâche, même quand il la
connaît (ex: "generateSPG" → "SPG generated").

=== Constat 3 — Le bridge codebase hardcode les métadonnées manquantes

`codebase-plugin/src/main/kotlin/codebase/koog/VibecodingGraph.kt:713`
(`extractCurrentStep`) :

[source,kotlin]
----
return VibecodingStep(
    description = task.description,
    gradleTask = task.gradleTask,
    expectedOutput = "BUILD SUCCESSFUL"  // ← hardcodé
)
----

Idem `VibecodingGraph.kt:741` (rollback). Drift : toutes les tâches,
quelle que soit leur nature, sont vérifiées contre `"BUILD SUCCESSFUL"`.
Une tâche `generateSPG` qui produirait `"SPG generated"` sans
`"BUILD SUCCESSFUL"` dans sa sortie serait marquée FAILED par erreur
(ou inversement). Le planner LLM sait pourtant la différence — mais ne
peut pas l'exprimer.

=== Constat 4 — Le prompt LLM ne demande pas les métadonnées

`planner-plugin/src/main/kotlin/planning/IntentionPlanner.kt:135`
(`buildPromptInternal`) — schéma JSON de sortie :

[source]
----
"tasks": [
    {
        "description": "<task description>",
        "gradleTask": "./gradlew <task>",
        "toolType": "GRADLE",
        "target": ""
    }
]
----

Pas de `expectedOutput`/`maxRetries`/`verifyHook`. Le LLM n'a aucun moyen
de les fournir, même quand il les connaît.

== Décisions architecturales

. *Portée EPIC* : étendre `contracts.agent.GradleTask` (N0) avec 3
  champs de vérification optionnels (defaults backward compat) + étendre
  le prompt LLM pour les demander + étendre le bridge codebase pour
  consommer la vraie valeur. *Pas de nouveau type* — on enrichit le N0
  existant (pattern PLN-CONTRACTS US-1 qui a ajouté `toolType`/`target`).

. *Backward compat critique* : les 3 nouveaux champs doivent avoir des
  defaults qui préservent le comportement actuel :
  * `expectedOutput: String = "BUILD SUCCESSFUL"` (valeur hardcodée
    actuelle du bridge — default identité)
  * `maxRetries: Int = 3` (valeur default actuelle de `VibecodingStep`)
  * `verifyHook: String? = null` (valeur default actuelle)
  Avec ces defaults, le bridge codebase qui construit `VibecodingStep`
  à partir de `GradleTask` produit exactement le même `VibecodingStep`
  qu'aujourd'hui → zéro régression.

. *Dépendance cross-borough BOM* : `agent-contracts` 0.0.2 → 0.0.3 (bump
  avec les 3 nouveaux champs + invariants). Publication Maven Central
  (MEMPHIS). Backward compatible (defaults Kotlin data class).

. *Dépendance cross-borough codebase* : `VibecodingGraph.extractCurrentStep`
  + rollback (2 sites) remplacent le hardcodé `"BUILD SUCCESSFUL"` par
  `task.expectedOutput` (la vraie valeur du plan). Si planner ne fournit
  pas → default `GradleTask` = `"BUILD SUCCESSFUL"` (identique au
  comportement actuel).

. *Dépendance planner-plugin* : `LLMTask` + `LLMResponse.toPlan()` +
  prompt LLM étendus pour demander/propager les 3 champs. Bridge
  `LLMTask.toTask()` les mappe. Si LLM ne fournit pas → defaults
  `GradleTask`.

. *Non-régression critique* : `PlannerIntegration.kt` (codebase) appelle
  `IntentionPlanner.plan()` puis construit `PlanState`. Le pont
  `Plan → VibecodingStep` via `extractCurrentStep` doit produire un
  `VibecodingStep` identique à aujourd'hui si le LLM ne fournit pas les
  métadonnées (defaults backward compat).

. *Invariants N0* :
  * `expectedOutput` non-blank (une tâche doit déclarer ce qu'elle
    produit — même si default "BUILD SUCCESSFUL")
  * `maxRetries > 0` (pas de retry infini, pas de retry nul — une tâche
    s'exécute au moins une fois, retry minimum 1 = 1 seule tentative)
  * `verifyHook` nullable (pas toutes les tâches ont un hook custom)
  * `maxRetries <= 10` (borne supérieure anti-abus — éviter qu'un LLM
    halluciné émette `maxRetries = 9999`)

. *Méthode* : baby-step DDD/TDD/BDD, 3 niveaux tests/US
  (unit → functional → cucumber), English only code/Gherkin.

. *Ordre* :
  * US-0 cadrage (cette session)
  * US-1 BOM cross-borough (N0 étendu + pub MEMPHIS) — indépendant
  * US-2 planner consomme N0 étendu (LLMTask + toTask + prompt)
  * US-3 codebase bridge consomme la vraie valeur (2 sites)
  * US-4 Cucumber BDD end-to-end
