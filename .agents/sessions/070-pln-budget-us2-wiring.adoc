== Objectif

Remplacer le budget fixe `ChannelBudget` (40/30/20/10) dans
`DecomposeIntentionTask` par le budget dynamique `BudgetAdapter` (EPIC
PLN-BUDGET US-1, domaine `planning.budget`). Le budget dynamique tronque
les 4 canaux selon la similarite cosinus+softmax avec l'intention.

== Constat initial

`DecomposeIntentionTask.kt:101-139` construisait un `CompositeContext` typé
via `ChannelBudget` (40/30/20/10 fixe) *uniquement pour le log*
`[planner] Multi-canal activé`. Le resultat `typedCtx` n'etait **jamais
injecte dans le LLM** — l'appel `IntentionPlanner.plan(eagerContext = eagerCtx, ...)`
utilisait le contenu original non tronqué.

Le budget fixe allouait 3200 tokens EAGER quoi que l'intention soit. Un
intention "planifier formation AFNOR" et "generer README" recevaient le
même budget.

== Design DDD — Extraction `BudgetWiring`

Extraction de la logique budget+log dans `BudgetWiring` (object pur,
domaine `planning.budget`) pour que la tâche Gradle délègue et que la
logique soit testable unitairement sans GradleRunner.

`BudgetWiring.resolveBudgetedContexts(intention, eagerCtx, ragCtx,
graphifyCtx, docsCtx, totalTokens=8000, log={})` :
. Detecte `hasMultiChannel` (au moins 1 canal non-blank).
. Si pas multi-channel : retourne `RelevanceContext` original sans log
  (economie d'encre).
. Si multi-channel : appelle `BudgetAdapter.applyRelevanceBudget` (US-1)
  qui mappe 4 canaux -> Map -> `RelevanceBudget.compute` (cosinus+softmax)
  -> `ChannelScore` -> `RelevanceContext` (4 String tronquées).
. Log `[planner] Multi-canal activé : E=N R=N G=N D=N tokens` avec
  `ContextChannel.estimateTokens` (N0, toujours dans le classpath).

`DecomposeIntentionTask.decompose()` :
. Appelle `BudgetWiring.resolveBudgetedContexts` AVANT l'appel LLM.
. Log apparait AVANT l'appel LLM (testable sans Ollama réel —
  `buildAndFail` avec `localhost:1` suffit pour valider le log).
. Passe le contenu **budgetisé** (et non original) a `IntentionPlanner.plan`.
