== Non-régression critique

`PlannerIntegration.kt` (codebase) appelle `IntentionPlanner.plan()` puis
construit `PlanState`. Le pont `Plan → VibecodingStep` via
`extractCurrentStep` produit maintenant un `VibecodingStep` portant les
vraies métadonnées du `GradleTask` N0. Si le LLM omet les métadonnées
(S-065 defaults `?: "BUILD SUCCESSFUL"` / `?: 3` / `?: null`), le
`GradleTask` est identique au legacy → `VibecodingStep` identique →
zéro régression. Vérifié : 881 tests codebase 0 failures.

== Décisions architecturales

. *Visibilité `internal`* : `extractCurrentStep` rendu `internal` pour
  testabilité (même package `codebase.koog`). Pattern `buildReplanPrompt`
  déjà `internal` (ligne 473). Pas de fuite d'API publique.
. *Site 2 fallback légitime* : le fallback rollback (ligne 741) n'a pas
  accès à un `GradleTask` (pas de plan extractible). Conserver le default
  N0 `"BUILD SUCCESSFUL"` est le bon comportement — c'est un fallback
  d'erreur, pas un hardcodage caché. Log warn ajouté pour traçabilité.
. *Bump codebase 0.0.2 → 0.0.3* : aligne codebase sur planner (S-065).
  Aucune régression (0.0.3 est backward compatible, juste +3 champs
  avec defaults).
