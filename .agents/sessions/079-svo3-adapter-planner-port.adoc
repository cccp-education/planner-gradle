== Design cross-borough

* Le service Gradle ne peut pas transporter un objet Kotlin arbitraire
  via ses params sérialisables → le port vit dans `PlannerPortRegistry`
  (JVM-wide), le service forwards.
* Côté codebase (SVO-4, prochaine session Queens) : résolution par le nom
  canonique `plannerPortService` + fallback `PlannerPort.NoOp` (le
  service `port()` fait déjà ce fallback lui-même).
* Cycle N1↔N2 reste mort : planner importe `codebase.koog.plannerport.*`
  (flèche unique N2→N1, pattern S-096/S-199/S-256).
